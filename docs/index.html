Overview

RixGPT is a character-level GPT whose entire forward pass is pure Eiffel. RIXGPT_MODEL reads a self-describing RIXG weights file through RAW_FILE and a MANAGED_POINTER, widens its fp16 tensors into a REAL_64 buffer, and then generates one character at a time through a KV-cached transformer — attention, GELU, layernorm and top-k sampling all written out in Eiffel, with no Python, no GPU and no C library beyond KERNEL32.dll. RIXGPT_APP wraps it in a console REPL: type a few words, press Enter, and about 400 characters come back.

Part of the Simple Eiffel ecosystem.

Status

0.1.0 — first public release. The program was built and shipped as a Windows installer on 2026-07-14; this release brings its source under version control and onto the simple_* fleet pattern. Clean release build, zero errors, zero compiler warnings.

Be clear about what this is. It is an inference engine, not a training framework: there is no backward pass, no optimizer and no tokenizer training here. It reads weights someone else produced and runs them forward.

And be clear about what the model is. A 10.9-million-parameter character model imitates a style. It knows no facts. Every sentence it produces is invented, including the ones that sound like citations. The program says so itself on startup, and that warning is not decoration.

What Is Not in the Repository

The repository is the Eiffel front-end and nothing else. These are deliberately absent, and excluded by .gitignore:

Absent What it is
model.bin The trained weights, about 21 MB
bin/ The runnable folder — RixGPT.exe beside model.bin
installer/src/ The Inno Setup staging folder, which holds a copy of both
installer/RixGPT-Setup.exe The compiled installer, about 21 MB

The weights are produced by Larry Rix's private training pipeline, from his own writing, and are not distributed here. installer/RixGPT.iss is source and stays: it documents exactly how the shipped installer is assembled. Without a model.bin the program builds and starts, prints the path it could not find, and exits — which is the intended behavior, and the reason a compile is the acceptance test this repository can offer.

The RIXG Weights File

RIXGPT_MODEL.make reads a self-describing header, so one binary serves any model shape. Everything is little-endian and every integer is 32-bit.

Bytes Field
4Magic — the ASCII characters RIXG
4Format version
4dtype, present only when version ≥ 2: 0 = fp32, 1 = fp16
5 × 4n_layer, n_head, n_embd, vocab_size, block_size
4Vocabulary count, equal to vocab_size
vocab_size × 4The Unicode code point of each vocabulary symbol — this is the tokenizer
restThe weight tensors, back to back, in serialization order

There is no tensor-name table. The loader walks the same fixed order the trainer wrote and records a float offset per tensor: token embedding, position embedding, then for each block ln1, the fused QKV projection, the attention output projection, ln2, and the two MLP layers, and finally the closing layernorm. The output head is not stored separately — the logits are read straight off the token embedding, so input and output embeddings are tied.

The shipped model.bin declares version 2, dtype 1 (fp16), 6 layers, 6 heads, n_embd 384 (head dimension 64), a vocabulary of 316 code points and a context window of 256 characters — 10,867,200 weights, the 10.9 M of the description.

How the Inference Works

fp16 by hand

Eiffel has no binary16 type, so half_to_double decodes the sign, exponent and mantissa of each 16-bit pattern arithmetically, subnormals included, into a REAL_64 buffer read once at load time.

One token at a time

forward handles a single position and appends its keys and values to caches sized n_layer × block_size × n_embd. Prompt characters stream through the same path, so a continuation never re-runs attention over text it has already seen.

Causal for free

Generation is strictly left-to-right and the cache only ever holds positions 0 .. pos, so there is no mask to build. The loop simply stops at pos.

GELU without a library

erf is the Abramowitz & Stegun 7.1.26 rational approximation, with error below 1.5 × 10−7. That is what makes the exact GELU affordable in pure Eiffel.

Sampling

Temperature scaling, a top-k floor found by partial selection sort, softmax, then an inverse-CDF draw from an xorshift32 stream. The app reseeds each turn from the clock, the prompt's hash and the turn number.

Validated numerics

The engine was ported from a numpy reference which itself matches PyTorch to 6 × 10−6 on the logits.

Building and the Distributable

cd /d/prod/simple_rixgpt
/d/prod/ec.sh release -config simple_rixgpt.ecf -target simple_rixgpt_app

release finalizes twice and leaves both binaries in EIFGENs/simple_rixgpt_app/F_code/: simple_rixgpt_lean.exe, with assertions compiled out, is the one that ships as RixGPT.exe; simple_rixgpt_dbc.exe keeps the contracts in. The lean executable links against KERNEL32.dll only.

A distributable is a folder, not a zip and not a single file. It holds exactly two things, side by side, and you run it from a command prompt in that folder: 

RixGPT\
    RixGPT.exe        (the finalized lean binary, renamed)
    model.bin         (the weights)

cd /d D:\path\to\RixGPT
RixGPT.exe

With no argument the program looks for model.bin in the current directory, which is why the two files must sit together and why the folder is the unit you copy. installer/RixGPT.iss builds that same folder as a Windows installer, adding a Start RixGPT.bat wrapper that runs chcp 65001 first so em-dashes and Hebrew render in the console.

Testing

/d/prod/ec.sh test -config simple_rixgpt.ecf -target simple_rixgpt_tests
./EIFGENs/simple_rixgpt_tests/F_code/simple_rixgpt.exe

This is a compile proof, not behavioral coverage, and the test file says so in its own class note. RIXGPT_MODEL has exactly one creation procedure and it takes a path to a weights file, so nothing in the class can be exercised without the weights this repository does not carry, and a fabricated model would prove nothing about the real one. What the target does prove is that both classes type-check and finalize — which is what breaks first when the engine is edited.
